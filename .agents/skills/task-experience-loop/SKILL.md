# 任务经验闭环

只维护当前项目。用户要求只读分析时保持工作区不变。跳过一次性查询、普通编辑和没有可复用决策的任务。

## 开始时检索

先读 `LESSONS.md` 的“强制检查”，再从主题索引进入 `docs/lessons/`，用组件名、错误文本或预防动作检索。按当前实现核对适用范围。旧编号的去向见根文件的“旧编号索引”。

需要查未合并线索时，在 `.agents/experience/sessions/` 按文件头的 `In progress` 状态筛选，优先读最近的相关日志，最多三份。`Consolidated` 日志只在按编号、任务或证据追溯时读取。

## 执行中留证

遇到需要多次尝试的故障、非显然的约束、值得复用的验证路径、用户确认的持久决定，或影响验收结论的缺口时，再创建本任务的日志。首次写入前确认 `.gitignore` 忽略 `.agents/experience/`，缺失时补上。使用[经验文件格式](references/ledger-format.md)记录实际观察、决定性证据与未决事项，长任务在中断前保存。

凭据、个人信息、签名 URL 和原始敏感配置须脱敏。查验优先使用现存证据，避免仅为记经验重跑收费或有副作用的操作。

## 收尾时决定去向

1. 逐项区分已验证结果、仍待确认的问题和未运行的检查。先问“下次遇到什么情形，这条经验会改变哪个动作？”答案具体、适用于当前项目、证据可复查，才考虑长期收录。首次遇到但代价高的坑同样可以收录。
2. 按根因和预防动作检索已有条目。相同则合并。已有规范或测试直接表达的事实，在日志里指向原处即可。用户确认的持久决定沿用权威来源，有冲突时先核对。一次性决策、常规成功与未验证猜想留在日志。
3. 确需新增时在对应主题文件按模板写短条目。只有同一问题在不同本地日期实际再次发生，才增加 `Seen`。成功复用、引用、重试和事后核对分别记在日志，不增加复现日期。已核实且在三个不同日期出现时，在主题中标为 `Promoted`，并在根索引增加链接到条目的 `LC-` 强制检查。
4. 规则被替代时保留旧编号、替代日期和去向，将旧正文移出经验明细。项目已经移除某项功能或技术栈时，同时清理其专属条目、过程日志及残留引用。混合记录只保留仍适用且有独立证据的部分。并行修改前重读目标条目及索引，保留他人的日期和证据。
5. 日志写明合并结果和遗留问题后，标为 `Consolidated`。这个状态表示经验已经核对归类；业务验收按各事件的证据另行判断。没有值得长期收录的经验也可以收尾。
