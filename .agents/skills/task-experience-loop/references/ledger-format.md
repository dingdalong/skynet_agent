# 经验文件格式

`LESSONS.md` 随仓库提交，供后续任务按需检索。`.agents/experience/sessions/` 由 Git 忽略，保存本地原始证据。共享规则须给出仓库中可复查的测试、规范、提交或最小复现方法；本地日志可作为补充。

## 过程日志

一个任务一份 `.agents/experience/sessions/<YYYYMMDDTHHmmss>-<slug>.md`，使用本地时间，同名时追加序号。只记录影响判断的事件。

```md
# 任务经验日志

- 状态：In progress
- 任务：<目标>
- 日期：<YYYY-MM-DD>
- 范围：<子系统或入口>

## 事件

### E1: <触发场景>

- 观察与处理：<观察到什么，哪个尝试改变了判断，采取了什么动作>
- 验证：<Verified / Open / Not run>；<决定性证据或缺口及影响>
```

`Verified` 需有与结论直接对应的证据，例如同一用例修复前失败、修复后通过。根因或效果仍待确认时写 `Open`。确定未执行的检查写 `Not run` 并说明原因。根据需要在同一事件里分别写明各项结果。

收尾时把文件头状态改为 `Consolidated`，并在文件头增加两个按需填写的字段：

```md
- 合并结果：<新增或更新的 L-ID、仅复用的 L-ID，或只留本日志的理由>
- 遗留：<尚未核实的结论和缺失的验证；没有时省略>
```

核对旧日志的引用时，同时对照条目标题与根因。复用写入“合并结果”，实际跨日复现才更新长期条目的 `Seen`。

## 长期经验

根 `LESSONS.md` 只放强制检查、主题索引和旧编号索引。选择 `docs/lessons/` 中对应的主题，每条经验只维护一份正文。主题变化时同步根索引。证据链接从主题文件按相对路径指向当前仓库的实现、用例或规范。

```md
<a id="l-nnn"></a>

### L-NNN <触发场景和需要采取的动作>

<根因、验证方式与必要的适用边界> [证据](../../仓库内路径)

Verified · Seen: 1× (YYYY-MM-DD)
```

使用稳定的小写编号锚点，改标题时保留锚点。分配新号前同时查看所有主题、旧编号索引与保留号段，取已分配最大号的下一号。并行写入前复核编号和目标条目。

合并同一根因与预防动作时，核对原始证据，按不同本地日期取并集。同日多次触发只计一次。成功复用、相邻问题和规则接替保留各自出处。达到三个真实复现日期时在主题改为 `Promoted`，在根文件写 `LC-NNN` 并链接主题文件的 `#l-nnn`。

## 旧编号索引

合并或替代时在根索引记录旧编号、去向和日期。目标为现行条目时直链编号锚点，目标为规范时链接维护该规则的文档。失效条目写明移除原因，相关历史通过 Git 查阅。项目移除功能后，同时清理专属本地日志，混合日志保留仍有用的事实与证据。
