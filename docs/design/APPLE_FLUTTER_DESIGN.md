# Flutter Apple 设计规范

客户端使用统一的 Apple 风格，Flutter 官方 Cupertino 提供基础组件，桌面交互由共享 UI 包补齐。
本文是组件选择、样式和交互的统一查询入口，实际规格由 `client/packages/apple_ui` 提供。
桌面和移动共享语义、组件与业务流程，采用适合各自输入方式的布局和密度。
现有 Demo 用于可选预览和验收；开发页面无需登记画廊或同步新增示例。

macOS App 是视觉和动态体验的首个验收平台，确认后的真实页面作为其他平台的基准。
共享组件、布局和操作，材质与窗口宿主允许按平台增强；其他平台的能力限制不反向降低 macOS 表现。
官方指引提供依据，项目规格定义具体呈现，功能测试和令牌检查不能代替完整页面的视觉确认。

## 开发入口

1. 先查询本文，按用途选择官方控件或现有公共组件。
2. 颜色、文字与图标引用 `context.apple` 和 `AppleIcons`；间距优先采用 `AppleSpacing`。
3. 现有规则未覆盖的新用法先补本文。只有需要复用样式或行为时才补充 `apple_ui`，再由页面采用。

基础组件可以直接使用官方 Cupertino，不为统一命名建立一一对应的包装。
基础组件不依赖 Demo 或业务服务，业务状态由调用方持有。

## 设计依据

| 来源 | 用途 | 边界 |
| --- | --- | --- |
| [Apple HIG](https://developer.apple.com/design/human-interface-guidelines/) | 导航、控件用途、排版与辅助功能 | 保留建议与强制要求之间的区别 |
| [Apple Design Resources](https://developer.apple.com/design/resources/) | 官方组件结构、视觉与状态参考 | 资源适用的平台和系统版本需匹配 |
| 当前 macOS | 观察系统设置、菜单、工具栏及弹窗的外观和行为 | 截图像素不直接等同逻辑尺寸；观察不能证明内部实现 |
| [官方 Cupertino Examples](https://github.com/client/packages/tree/main/packages/cupertino_ui/example) | 官方基础控件用法 | iOS 控件不自动具备完整桌面交互 |
| [hig-mcp](https://github.com/aka-kika/hig-mcp) | 设计令牌与平台规则查询 | 检查数据来源、版本和适用平台；社区数值不作为 Apple 硬性规定 |

本机参考以 macOS 系统设置的分组表单、侧栏、搜索和层级为起点。AppFlowy 的克制视觉与 Astryx 的组件文档组织方式作为产品参考。
CDK 仅用于理解桌面交互实现，不继承其主题或控件外观。

## 语义令牌与视觉

令牌由 `apple_ui` 集中管理。颜色分为背景、表面、侧栏、主要文字、次要文字、边界、强调、选中和危险状态。
同时维护浅色、深色和增强对比度；组件使用语义值，不在业务界面另建颜色与文字规格表。
字号、间距、圆角和控件高度属于项目约定，不标成 Apple 统一要求。

macOS 使用系统 UI 字体及系统中文回退，代码使用等宽字体。不向其他平台打包 Apple 字体或系统图标资源。
图标使用官方 Cupertino 图标包，并保留依赖的许可声明。

### 文字角色

页面使用以下 `AppleThemeData` 文字角色，不在调用处重新设置字体族、字号、字重、行高或字距。
具体数值以共享主题为准，桌面与触控由同一角色解析为各自的密度。

| 角色 | 用途 |
| --- | --- |
| `pageTitle` | 一个页面的主要标题 |
| `sectionTitle` | 内容分组和弹窗标题 |
| `body` | 正文、一般控件文字和输入内容 |
| `label` | 字段标签、需要强调的简短说明 |
| `caption` | 时间戳等低优先级元信息 |
| `supporting` | 设置说明、表单解释等需要正常阅读的次要正文 |
| `code` | 代码、命令及需要等宽对齐的内容 |

主题同时提供 `eyebrow`、`button` 和 `emphasizedButton`，用于小标题与按钮内部样式。
文字颜色可以通过 `copyWith(color: ...)` 改用其他语义颜色。
桌面页面标题为 26、分组标题为 17、正文和设置标签为 14、说明为 13、元信息为 12；
这些是本项目规格，不是 Apple 的强制字号。触控继续使用较大的文字密度。

### 颜色与图标语义

| 意图 | 颜色 | 图标 |
| --- | --- | --- |
| 警告：存在风险，需要注意 | `warning` | `AppleIcons.warning`，填充三角感叹号 |
| 错误：任务失败，需要恢复 | `danger` | `AppleIcons.error`，填充圆圈叉号 |
| 成功：任务已完成 | `success` | `AppleIcons.success`，填充圆圈勾号 |
| 信息：中性说明 | `information` | `AppleIcons.information`，填充圆圈信息符号 |

常用操作和导航图标也由 `AppleIcons` 按含义命名。状态图标使用填充形态，普通操作和导航沿用映射中的线框形态，
页面不另选同义图标。新含义在共享映射中增加，不建立额外的图标登记系统。
反馈使用 `AppleStatusMessage`，同时显示图形、类型语义和文字；正文保持可读，不能只靠颜色区分。
动态结果按需使用 live region，静态说明关闭重复播报；恢复操作使用统一按钮。

### 间距与表面

通用间距优先使用 `AppleSpacing` 的 4、8、12、16、24、32 档位；与内容宽度相关的布局测量可由页面决定。
控件和表面圆角分别取主题的 `controlRadius`、`surfaceRadius`，分组表面使用 `AppleSurface`。
透明色和模态遮罩也引用主题，不在页面重新定义颜色值。

表面保持清晰，以背景、边界和适量层次组织内容。正文和表单优先可读性。
不依赖玻璃折射或连续动画表达状态。`AppleMaterialSurface` 用于浮动控制层和导航层，正文表面保持稳定。
Flutter 模糊与系统 Liquid Glass 分别标明；原生材质必须验证实际底层内容合成、裁剪、缩放、输入和动画。
系统减少透明度或增强对比度时使用清晰的不透明表面。

### 工作区视觉

- 桌面应用图标为 64，Dock 图标为 52，共用渐变、连续圆角、边缘高光与柔和投影；Chat 蓝色、设置银灰。
- Dock 单元宽 56、间距 12、水平内边距 12、圆角 26，底座高度约 80；按钮不叠加隐含 padding。
- 壁纸具有柔和的曲面层次；浅色与深色分别校准。导航层和浮动层使用适量材质、边界与阴影。
- 设置侧栏、标题和分组保持对齐；说明使用 `supporting`，壁纸名称使用 `body`，不缩成元信息。
- 指针悬停、按压、选中与键盘焦点分别表达；指针操作不显示多余焦点框，键盘和辅助功能保留单一焦点环。
- 分屏调整按实际区域重新布局，不横向拉伸文字；打开应用与后台缩略可以使用空间缩放。

## 密度与响应式

- 桌面强调内容密度与精确操作，触控强调命中区域；可见尺寸和命中区域分别验证。
- 字体和控件随文字缩放增长，不用固定高度裁剪内容。长中文、错误说明与多行输入可以自然换行。
- 根据组件实际分配到的空间调整布局；不使用物理屏幕尺寸或横竖屏直接决定工作区。
- 桌面可使用侧栏与可调整分栏。窄窗口保留目录入口；手机使用逐级导航，平板使用适合触控的分栏，不因横屏直接套用桌面工作区。
- 相同内容空间、主题、输入方式和状态下，共享内容区保持一致。窗口控件、系统菜单、快捷键、返回、安全区和虚拟键盘由宿主适配。
- 画廊的宽度预览只验证布局，不等于移动设备、触摸、安全区或虚拟键盘验收。

## 组件与交互

优先直接使用 Cupertino。封装只用于统一语义令牌、密度或补齐桌面交互，不重写框架已有的文本编辑、选择和导航能力。
应用层只管理展示或业务状态，基础组件不依赖画廊。

### 应用工作区

客户端外壳采用 iPad 式桌面与 Dock：应用打开后铺满客户端内容区，Dock 仅在完整桌面显示，不占用应用布局空间。
各端共用应用状态、组合、动效和可见导航入口；宿主窗口的全屏状态由宿主管理。

| 设备 | 工作区导航 | 分屏 |
| --- | --- | --- |
| 桌面 | 应用顶部右侧提供“返回桌面”和“后台应用”；桌面提供后台入口，后台提供返回桌面入口 | 应用内部把手与分隔条，按内容宽度启用 |
| 手机 | 应用顶部右侧提供“返回桌面”和“后台应用”；桌面提供后台入口，后台提供返回桌面入口 | 始终单应用，隐藏布局把手 |
| 平板 | 与手机相同的可见导航入口 | 应用内部把手与分隔条，按内容宽度启用 |

所有平台统一使用顶部导航，不显示仿系统底部指示条，不使用底边上滑或停顿导航，也不通过延迟或屏蔽系统手势实现工作区操作。
按钮位于安全区内，命中区域至少 44×44 逻辑像素，使用房屋和叠放矩形图标及可访问名称。
设置详情的返回操作仍只返回设置列表；不复用它来返回桌面。打开或恢复应用后，焦点放在顶部工作区入口；
通过键盘安排布局后保留布局把手焦点，支持连续方向键操作。空后台的焦点放在顶部“返回桌面”。
原生 App 与 Web 沿用相同导航规则，横屏、浏览器桌面模式及外接键鼠不切换导航方式。
设备类别不随窗口宽度或当前指针变化；窗口宽度只决定分屏和内容布局，不把桌面窄窗口当成手机。
设备类别由共享宿主适配提供，Web 的设备识别在接入对应平台时验证。

应用内部拖动共用鼠标和触屏逻辑；系统边缘、页面滚动与虚拟键盘交互由宿主管理。
依据 Apple [Gestures](https://developer.apple.com/design/human-interface-guidelines/gestures) 避免与系统手势冲突的建议；安全区布局不等于取得系统边缘手势的控制权。

从应用顶部布局把手向左或右拖动，直接将应用放在对应侧，另一侧显示桌面；松手前拉回原位可恢复原布局。
“应用＋桌面”与“双应用”都是正式分屏状态，共用比例调整；从桌面打开另一个应用时填入桌面所在侧，保持当前比例。
分屏不要求应用位于 Dock。每个应用只有一个实例，桌面中已在另一侧打开的应用有明确状态，不再创建第二份。

桌面与平板支持交换位置及恢复全屏；分隔条接近 1/3、1/2、2/3 时吸附，其余位置可自由调整，
每侧至少 360 逻辑像素，只启用当前空间能容纳的吸附点。分隔条拖到边缘直接将较大一侧的应用或桌面铺满，松手前拉回可继续分屏。
拖动过程直接呈现实际布局，不显示落位蓝框或确认提示；松手保留当前结果，取消手势恢复原组合与比例。
宽度不足时暂时显示当前应用，扩大后恢复组合和比例；手机始终使用单应用布局。
后台保留页面状态和分屏组合，上滑卡片关闭对应应用，分屏中关闭一侧后该侧显示桌面。
轻点后台卡片以外的区域返回桌面，无后台应用时也能正常退出；返回桌面不关闭应用或重置页面状态。
手势区域可识别、可聚焦，键盘与辅助功能入口使用相同状态操作；内容滚动不触发外壳拖动。

正式客户端位于 `client/apps/client`，复用本文的共享规格。Chat 当前为空白布局应用，真实业务另行接入。
运行时、表现订阅与异常恢复遵循[客户端运行时](../architecture/CLIENT_RUNTIME.md)，
页面不持有业务资源的释放权。功能验证与视觉确认分别记录，以实际 macOS App 为准。

Flutter 工作区由正式客户端实现，沿用本文的共享规格。应用图标与壁纸使用主题中的工作区颜色，
不打包系统资源。顶部导航命中区域至少 44×44，正文与设置使用桌面密度。
后台卡片使用不可操作的内容摘要；真实应用保留唯一实例。原生菜单与顶部按钮调用同一状态入口。

### 工作区动效

动效表达应用、桌面和后台卡片之间的位置关系。以下时长和曲线是项目默认值，不是 Apple 官方常量；
动效方向、连续性与流畅度以 macOS App 实测校准。

| 用途 | 默认时长 | 行为 |
| --- | --- | --- |
| 按压与开关 | 120ms | 图标轻微按压、开关滑动，反馈即时 |
| 应用打开与返回 | 320ms | 从点击的桌面或 Dock 图标展开，返回时收回桌面图标；无可见来源时从中心轻微缩放展开 |
| 后台进入与恢复 | 320ms | 当前应用缩入对应卡片，恢复时从卡片展开；组合的应用及桌面保持原比例 |
| 分屏、换位、恢复全屏 | 220ms | 直接过渡到真实内容区域，不加落位蓝框或确认阶段 |
| 后台空白返回桌面 | 220ms | 卡片轻微收缩淡出，桌面与 Dock 显现 |
| 后台关闭 | 180ms | 卡片继续向上退出；其他卡片以 220ms 补位，不足关闭距离则以 220ms 归位 |

统一减速曲线为 `cubic-bezier(0.2, 0.8, 0.2, 1)`，不增加明显弹跳。
时长和曲线集中维护，不由页面逐个设置；Flutter 引用共享 `AppleMotion`。

所有平台通过顶部按钮触发相同的返回或后台过渡。
分隔条自由调整与卡片拖动直接跟随指针，不为每一次移动叠加缓动；离散布局切换才执行短过渡。
用户反向操作时，从当前画面接续动画，未松手仍可拉回原布局。

应用状态和布局先独立确定，动画结束只清理显示层，不提交业务状态。过渡不屏蔽新输入；
新操作接管当前画面，取消手势恢复已确认组合与比例，尺寸变化取消手势，页面隐藏后立即呈现正确终态。
离场显示层不可接收指针或键盘事件、不进入辅助功能树，不创建第二个应用实例，也不复制可操作标识。

系统或应用任一方开启减少动态效果时，取消空间位移、缩放与跟手变形，立即显示结果；
运行中开启也立即结束现有动画。减少动效不更改手势判定、应用状态或键盘操作。

### 控件选择

| 场景 | 统一入口 |
| --- | --- |
| 少量有限选项中选择一个值 | `AppleSelect<T>`；当前值、选项和变更回调由调用方提供 |
| 执行复制、导出、删除等命令 | `AppleMenuButton`；使用动词描述操作 |
| 即时生效的二值设置 | 官方 `CupertinoSwitch` |
| 一组可同时选择的选项 | 官方 `CupertinoCheckbox` |
| 可见的互斥选项 | 官方 `CupertinoRadio`；少量并列切换可用分段选择 |
| 文本与表单输入 | `AppleTextField`，标签由页面持久显示，分组可使用 `AppleFormRow` |
| 需要用户确认的操作 | `showAppleConfirmation` |
| 警告、错误、成功和信息 | `AppleStatusMessage` |
| 进行中的任务 | 官方 `CupertinoActivityIndicator`，同时说明正在进行的工作 |

`AppleSelect` 是有当前值的单选控件，关闭或取消不改变当前值；已选项带勾号，禁用项不可选择。
空值显示占位文字，无可用选项或无变更回调时禁用。选项值必须唯一，非空当前值必须对应一个选项。
桌面与触控共用实现，触控使用触控密度；菜单可滚动、长文字可换行，触发器的长值保留可访问的完整文字。
大量候选、远程搜索和多选应按具体业务定义独立交互，不套用短列表下拉。

- 按钮区分主要、次要、文字与危险操作，提供悬停、按压、焦点和禁用反馈。图标按钮有可访问名称。
- 输入框有持久标签，错误在字段附近说明原因与修复方式。编辑内容不因主题、密度或辅助功能切换丢失。
- 菜单支持方向键、Enter、Escape、外部点击关闭和触发位置焦点恢复；桌面支持右键，触控保留可见入口。
- 弹窗内焦点闭环；Escape 取消，安全默认操作允许 Enter 确认。危险操作不自动确认。
- 可调整分隔条支持拖动、键盘和辅助功能增减，三种入口使用同一尺寸约束。
- 动画可中断，正确性不依赖结束回调。减少动效时保留即时状态反馈。

## 自动检查与验收

`make client-check` 执行格式、分析、UI/导入边界检查和组件测试，并纳入 `make check`。
检查扫描 Flutter 自有应用和共享包的 `lib`：颜色和文字规格集中在主题，原始图标集中在共享映射。
检查基于解析后的 Dart 元素，支持导入前缀与类型别名，忽略注释、示例字符串和生成文件。
不限制直接使用官方 Cupertino，也不自动判断页面应选哪种控件或每个布局尺寸是否合适。

改动公共样式后验收受影响的真实页面；业务尚未接入时使用现有 Demo。
新增公共行为补充组件测试，并通过实际 macOS App 的端到端流程验证。

## 辅助功能与审查

提供正确的可访问名称、角色、选中与启用状态，焦点始终可见。信息不能只依赖颜色。
普通文字按适用 WCAG AA 规则核对，控件边界和焦点也需可辨识；透明颜色必须按实际合成背景计算。
系统的增强对比度与减少动效优先；画廊可以模拟相应状态，但模拟不作为系统同步验收。

工具分工：hig-mcp 查询依据；Sosumi 检索 Apple 原文；hig-review 提供清单、引用与对比度辅助；
Dart/Flutter MCP 负责分析、测试与运行检查；Computer Use 检查实际原生窗口。
