# 客户端设计规范

客户端保留操作系统式工作空间布局，采用官方 shadcn/ui 的 Nova 风格。
macOS 原生 App 是桌面体验基准，iPhone/iPad 使用同一套视觉语言并适配触控。
宿主保留 React Native，子应用使用官方 shadcn Web 组件，两者共用视觉与动作规范。
新平台复用工作区组件与令牌，通过平台适配处理系统能力，不复制整套页面。

## 统一入口

| 需求 | 查询与实现入口 |
| --- | --- |
| 颜色、字号、圆角、动态节奏、工作区尺寸 | `client/packages/tokens/tokens.json` |
| CSS 与 React Native 主题 | `tooling/generate-tokens.mjs` 生成，禁止直接修改产物 |
| 按钮、下拉、开关、分段选择、对话框、警告 | `client/packages/ui/src/components/ui`，通过官方 CLI 添加 |
| 组件 API 与新组件检索 | 项目 shadcn MCP、官方 shadcn 文档 |
| Web 图标 | Lucide；警告 `AlertCircle`、成功 `Check`、删除 `Trash2` |
| 原生宿主图标 | `packages/workspace/src/platform.tsx` 定义语义名，苹果平台入口映射为 SF Symbols |
| 新应用结构与边界 | 项目 `client-subapp` skill、客户端运行时规范 |

不要求建立组件画廊。需要新控件时先查公共包与官方组件；新增共同用法时在此规范登记。
RN 宿主只复用工作区所需的小型公共组件，不另造完整的 shadcn 原生复刻库。
官方组件作为项目源码维护，不为每个控件增加一层包装。官方组件原有无障碍结构和键盘行为必须保留。

## 视觉语言

- 中性浅色与深色主题，使用 `background`、`card`、`muted`、`foreground`、`primary`、
  `destructive` 等语义令牌。应用不能私自建立另一套全局主题。
- 使用系统字体。正文与表单标签保持可读的桌面尺寸；页面标题使用统一标题规格。
  侧栏、表单说明与状态文字保持清楚层级；分屏变窄时让内容重排，禁止缩放整段正文。
- Web 按钮与输入框使用 shadcn 焦点样式。原生图标按钮保留键盘和辅助功能入口，
  不使用系统默认的粗黑选择框；悬停、按下与键盘焦点应能区分。
- 标准选择使用 `Select`；少量互斥选项使用 `ToggleGroup`；布尔设置使用 `Switch`。
  提示使用 `Alert`，危险操作确认使用 `AlertDialog`，加载使用 `Skeleton`，空状态使用 `Empty`。
  表单使用 `FieldGroup`、`Field` 和关联标签；对话框必须有标题。
- 自定义颜色仅用于壁纸、图标品牌和主题预览等明确的图形示例；业务控件使用语义颜色。
- 每种壁纸均有浅色和深色版本；桌面、分屏中的桌面、后台与设置中的预览使用同一组主题令牌。
  切换外观立即生效，跟随系统时同步系统主题。
- 宿主材质和系统窗口可原生增强，但不得改变共享功能入口、动作语义或业务数据。
- 桌面与 Dock 图标共用启动器反馈：悬停轻微抬起与放大，按下轻微收缩与变淡，
  松开或移出平滑恢复；键盘焦点始终标在固定的点击区域，运行标记不随图标移动。
  反馈使用 `launcher` 与 `motion.quick` 令牌，macOS 由原生合成层执行，
  不通过 JS 逐帧更新。减少动态效果时保留焦点和按下明暗，关闭缩放与位移。
  图标与 Dock 使用 `elevation` 中的浅深色双层阴影，生成 CSS 与原生共用规格；
  阴影不得被图标容器裁切，也不以不透明的大块背景代替层次。

## 工作区交互

桌面显示所有已安装应用，Dock 提供相同入口和运行标记。打开应用后占满工作空间内容区域，
隐藏 Dock，不保留壁纸边距、圆角浮窗或额外的工作区工具栏。
主页、应用名称、分屏握柄、后台和关闭合并在应用顶部的一条工具栏；
系统窗口控件仍属于 macOS 窗口。返回桌面与查看后台使用明确入口，不依赖系统边缘手势。

触控控件命中区域至少使用 `touch.target`，输入字体至少使用 `touch.input`，不通过缩放页面塞入内容。
原生根视图提供安全区和键盘避让，Web 内容使用剩余视口，不重复计算系统 inset。
子应用入口声明 `viewport-fit=cover`，由宿主统一留出系统安全区。
根文档填满宿主提供的高度并固定滚动位置，页面只在自己的消息区、内容区或对话框内滚动；
不叠加原生滚动容器与整页滚动，不用屏幕高度代替可用内容高度。
分隔条扩大触控命中范围；可用宽度不足时隐藏标题分屏握柄，并保留后台切换与主页入口。
手机竖屏、横屏和 iPad 使用相同宽度断点。对话框在键盘视口内可滚动，
空状态在自身区域内滚动，不覆盖输入区。系统边缘手势保留给系统。

布局以容器的可用宽高、输入方式和宿主能力为依据，不按设备型号复制页面或添加尺寸补丁。
宽度决定侧栏、导航与分屏的重排；高度决定内容压缩与滚动。普通对话让消息区弹性伸缩，
标题与输入区总高度仍超过视口时，内容面板整体可滚动，输入和提交入口必须可达。
短视口编辑时优先显示输入与发送，临时收起会话标题、模型选择和键盘提示；退出编辑后恢复。
新增页面先定义伸缩、最小尺寸与滚动所有者，再验证断点两侧、短视口和内容增长；
平台入口只处理安全区、键盘及系统资源，不自行补页面边距。

拖动应用顶部握柄到左侧或右侧，平滑呈现“应用＋桌面”。松手提交，拖回原处恢复。
点击空白桌面的另一应用形成双应用分屏。布局变化不显示蓝色预告框。
分屏中的标题拖动只用于左右放置或交换，保留另一个应用和各自宽度；拖到中间不进入全屏。
分隔条支持三分之一、二分之一和三分之二吸附，吸附进入与离开使用不同阈值，防止抖动。
分屏时两侧宽度均不小于工作区的三分之一；首次到达边界先停在该档位，
从停住的位置继续向外拖过确认距离才预览另一侧全屏，拉回可以恢复分屏。
快速首次拖动即使越过边界，也先停在三分之一。松手提交当前可见预览，不在松手时突然切换布局。
全屏预览保留同一手势响应者，拉回无需重新按下。被收起的应用保留在后台；
保留侧是桌面时返回桌面。键盘与辅助功能按三档调整，在下限继续缩小执行同一收起操作。
窄窗口临时显示单应用，扩大后恢复原来的分屏组合。
尺寸和阈值的实现由共享几何规则与令牌维护。
工作区容器统一计算左右面板与分隔条的矩形，子应用只在分配到的区域内重排。
手势按开始时的容器宽度与累计位移更新；分隔条命中区域的父容器在预览期间保持稳定，
不能用移动后的分隔条局部坐标重新计算比例。窗口改变宽度时取消当前预览。

后台卡片点击恢复应用；向上拖动关闭，也提供可访问的关闭按钮。
点击卡片外区域返回桌面，空后台也一样。关闭应用会结束其运行时和资源；
返回桌面或进入后台保留可丢弃的界面缓存，复开直接恢复内容；表现重载只替换界面订阅。

应用场景使用固定层级：共享场景容器 → 平台过渡层 → 应用工具栏与 Web 内容。
共享容器统一拥有面板矩形、可见性、点击命中和辅助功能状态；后台场景继续保留，但不绘制、不接收输入。
容器的可见状态同时映射到原生 hidden 属性，保留子树；不能只靠透明度隐藏仍可被辅助功能发现的内容。
平台适配器只执行容器内部的过渡，激活状态只用于启动或停止动画，不能成为第二个显示状态源。
动画层即使收到迟到的完成、取消或属性恢复，也不能改变父容器的可见性。
不在同一原生属性上切换静态显隐值与动画值，不依靠层级数值、固定延迟或动画结束回调修正显隐。
关闭、重载与内存压力的释放策略和场景显示分别管理。

左右放置和交换使用宿主原生合成层的几何过渡，不通过 JS 每帧提交整个工作区的透明度和位置。
最终布局先提交，动画只改变表现值，窗口隐藏或过渡中断后仍呈现最终状态。分隔条直接跟随指针。
打开或恢复应用时，应用面板轻微缩放显现；进入后台时，卡片与提示平滑显现。
两者仅在进入时执行一次，后续状态更新不重播，不把过渡完成作为可操作或提交状态的条件。
动效参数集中在共享令牌，使用原生合成层执行，不让 JS 逐帧重排 Web 内容。
返回桌面时桌面保持静止，不播放上下位移。应用首屏使用已提交状态和正确主题，
内容准备好后轻柔显现，不让整个工作区变透明、露出壁纸或先显示默认设置页面。
减少动态效果和系统辅助功能设置优先，禁用几何过渡。

## Agent 对话

宽内容区域显示会话侧栏，窄分屏使用会话选择器；内容与输入区保持一致的最大阅读宽度。
消息使用官方 `MessageScroller`、`Message` 和 `Bubble`，由组件管理流式跟随与返回最新消息。
回答支持安全 Markdown，代码与工具输出复用 `CodeBlock`；思考和工具步骤使用 `Trace`，
明细默认折叠，状态使用统一图标和中文说明。远程 HTML、图片和链接不能获得 WebView 网络权限。
输入使用 `Field` 和 `InputGroupTextarea`，模型使用 `Select`，连接配置使用 `Dialog`。
工作目录使用 `Select`，添加本地项目调用系统目录选择器。连接新服务器显示原生来源授权确认；
本机远程执行使用明确的独立 `Switch`，默认关闭。
模型与目录选择在请求期间禁用，重复选择幂等，不通过插入错误横幅改变历史区域的高度。
Enter 发送、Shift + Enter 换行，输入法组合期间不发送。生成中提供停止入口，并允许准备下一条草稿。
触控输入时回车换行，点击发送按钮提交；硬件键盘也可用 Command/Ctrl + Enter 发送。
服务器确认取消后，仍等待任务终态才恢复发送；失败轮次按服务器的 retryable 标记提供重试。
连接状态与会话同步状态显式显示，失败保留输入，不自动重新执行发送或工具任务。

## 验收

检查完整原生页面的密度、Dock 比例、图标阴影、文本可读性、悬停、焦点、主题和动态效果。
分别检查普通窗口、窄窗口和双应用分屏；验证屏幕阅读器标签、键盘等效入口与减少动态效果。
打开卡顿使用实际 Release App 的性能采样定位，并在相同操作下复测；
CPU 采样和静态截图不能作为帧率测量结果。
`make client-check` 验证类型、令牌、导入边界和逻辑。原生交互使用 Computer Use 在最新本地 App 上验收。
截图只用于人工查看与排查，写入 `client/test-artifacts/`，不维护像素基线。
