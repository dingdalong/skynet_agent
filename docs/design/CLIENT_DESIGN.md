# 客户端设计规范

Astryx 是宿主和子应用共同的设计依据。从工作区宽度和用户当前的任务出发布局。每个面板都应能回答三个问题：正在使用哪个应用、如何切换、如何与另一个应用并排。

## 主题与组件

- 颜色按表面、主次文字、分隔线、焦点和操作状态选用 Astryx 语义令牌。字号、间距、圆角和动效从同一官方主题取得。用文字或图标配合颜色表达选中、运行和错误状态。
- React Native 宿主在构建时将官方主题转换为原生值，使用平台控件绘制并处理键盘、指针、触控与读屏。平台适配负责窗口装饰、安全区和系统图标。
- Web 子应用优先组合 Astryx 官方组件和布局，加载所选主题与组件的预编译样式。业务特有的布局或图形才补充局部样式。[官方样式说明](https://astryx.atmeta.com/docs/styling-overview)

## 分屏与多平台

- 同时提供可见的分屏操作和键盘或辅助功能等效入口。并排时，用户能辨认当前活动面板，调整比例、切换面板或结束分屏。反馈展示松手后实际得到的布局。
- 根据工作区实际可用宽度排布。桌面和 iPad 宽度充足时提供分屏和比例调节，窄窗口显示当前应用，可通过后台切换。重新变宽时恢复组合和比例。
- 每个面板独立处理内容重排和滚动。宿主处理安全区和软键盘占位，触控有足够命中面积，键盘焦点始终可见。减少动态效果后仍能辨别活动面板和操作结果。

## 评审与验收

桌面保留应用图标和底部居中的 Dock。应用名称标在桌面图标下方，Dock 以符号和运行点提供快捷入口。应用内的主页、应用名称、分屏、后台和关闭入口位于顶部工具栏。使用 Astryx Neutral 的浅深色主题。

在实际 App 验证应用的打开、调整与恢复，覆盖宽度变化、键盘、触控、浅深色和减少动态效果。应用数据与界面生命周期遵循[客户端运行时规范](../architecture/CLIENT_RUNTIME.md)。
