# 客户端编码与协作规范

本文件补充[仓库公共编码与协作规范](../编码与协作规范.md)，客户端架构入口见 [AGENTS.md](AGENTS.md)。
除特别说明外，下列命令均在仓库根目录执行。

## 组件与主题

- 宿主与子应用共用[客户端 Astryx 设计规范](../docs/design/CLIENT_DESIGN.md)。主题与组件 API 以项目使用的官方包版本为准。

- WebView 新增 Web 特性时，核对项目支持的 macOS、iOS 系统 WebKit。支持不一致时做能力检测或渐进增强，
  确保基础操作在目标 WebView 中可用。

## 测试用例

- 本机 macOS 界面验收和 Computer Use 统一执行 `make macos-test-app`，复用
  `client/test-artifacts/macos/skynet agent test.app`，应用标识固定为 `app.skynet.agent.test`。
  只有专门测试授权流程且用例需要新身份时，才创建单独的测试副本。
- 日常开发使用 `make dev`，`make client-check` 完成客户端静态检查、逻辑与原生集成测试；
  仓库级回归与验收频率遵循公共规范。
- 功能开发只在当前本地客户端验证视觉和交互，本地 macOS App 验证共享功能，不要求逐个平台构建或测试。
  静态检查、状态机测试、编译通过或浏览器模拟不能替代本地原生体验验收。
- 发布对应平台产品时，再验收该平台的兼容性、窗口、菜单、快捷键、输入法、主题、布局、安全区、
  原生依赖与打包产物；iOS 发布时覆盖 iPhone/iPad 与软键盘。
- 端到端范围按本次改动涉及的实际流程确定，使用 Computer Use 操作最新本地 macOS App 并验证最终界面结果。
- 聊天业务端到端按公共真实模型验收要求，从实际平台 App 操作出发，经对应运行时、WebSocket 网关和服务端处理，
  验证最终页面结果；工作区 E2E 不能替代这条完整业务链路。
- 日常操作使用开发态 App；原生宿主或构建时注入的配置修改后重启开发进程。
  端到端夹具可生成测试资源，无需生成正式 App／DMG；打包态验收使用最新产物。
- Computer Use 不可用时，继续后台检查和构建，并如实保留未完成的界面验收。
- `make check-full` 运行基础回归、服务端集成与客户端原生集成；界面验收通过 Computer Use 完成。
- 测试截图只用于排查和人工查看，不维护像素对比基线。截图及相关测试产物统一写入
  `client/test-artifacts/` 并忽略，不提交 Git；功能、布局、主题、颜色和无障碍断言继续保留。
