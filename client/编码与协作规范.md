# 客户端编码与协作规范

本文件补充[仓库公共编码与协作规范](../编码与协作规范.md)，客户端架构入口见 [AGENTS.md](AGENTS.md)。
除特别说明外，下列命令均在仓库根目录执行。

## 组件与主题

- 复用 `packages/ui` 和 `packages/tokens`。组件用法通过项目 shadcn MCP 与官方文档查询，
  不要求维护组件画廊。
- 颜色、字体、间距、状态图标与控件选择集中定义。共享令牌生成 CSS 与原生主题，
  不在各应用复制主题或自行绘制标准表单、对话框和状态控件。
- 新增用法先补[客户端设计规范](../docs/design/CLIENT_DESIGN.md)。

## 测试用例

- 日常迭代使用 `make dev` 验证当前功能，`make client-check` 完成客户端静态检查、逻辑与原生集成测试；
  仓库级回归与验收频率遵循公共规范。
- 功能开发只在当前本地客户端验证视觉和交互，本地 macOS App 验证共享功能，不要求逐个平台构建或测试。
  静态检查、状态机测试、编译通过或浏览器模拟不能替代本地原生体验验收。
- 发布对应平台产品时，再验收该平台的兼容性、窗口、菜单、快捷键、输入法、主题、布局、安全区、
  原生依赖与打包产物；iOS 发布时覆盖 iPhone/iPad 与软键盘。
- 端到端范围按本次改动涉及的实际流程确定，优先复用现有 macOS 原生夹具。
  `make client-e2e` 验证其覆盖的原生流程。
- 聊天业务端到端按公共真实模型验收要求，从实际平台 App 操作出发，经对应运行时、WebSocket 网关和服务端处理，
  验证最终页面结果；工作区 E2E 不能替代这条完整业务链路。
- 日常操作使用开发态 App；原生宿主或构建时注入的配置修改后重启开发进程。
  端到端夹具可生成测试资源，无需生成正式 App／DMG；打包态验收使用最新产物。
- Computer Use 不可用时，不自行切换到会占用当前桌面鼠标、键盘的 XCUITest。
  前台 UI 自动化必须先说明影响并由用户确认测试时段；仅有应用访问授权不代表用户允许接管前台输入。
  后台检查和构建继续执行，未完成的原生验收如实保留。
- 确认测试时段后使用 `SKYNET_FOREGROUND_UI_TESTS=1 make client-e2e`；
  `make check-full` 包含的客户端前台阶段同样遵循上述要求。
- 测试截图只用于排查和人工查看，不维护像素对比基线。截图及相关测试产物统一写入
  `client/test-artifacts/` 并忽略，不提交 Git；功能、布局、主题、颜色和无障碍断言继续保留。
