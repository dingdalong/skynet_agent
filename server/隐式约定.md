# 服务端隐式约定

## 登录与应用路由

- WebSocket 校验公共帧，已登录请求按 `app_id` 传递原始应用数据。请求与响应的命名遵循
  [公共隐式约定](../隐式约定.md#公共协议)。
- `logind` 处理 `LoginReq`，按用户名固定选择 `client`，绑定连接后返回 `UserIdentity`。
  `client` 校验连接及 WebSocket 来源，给每个应用请求附上已绑定的身份和连接 ID。
- 应用入口为 `src/service/app/<name>/init.lua`。应用私有的模块和资源放在同一目录，
  基础服务的私有模块放在 `src/service/<name>/`。`src/lualib/` 用于公共框架、协议和可复用的库。
- `.app_center` 登记每个应用的节点地址、实例代次和就绪状态。
  `client` 订阅目录并按版本更新。应用节点收到原始请求后解码并按用户名哈希选择 Actor。
  设备端只能发送已声明的协议请求。普通目录查询返回应用名称，管理员授权绑定当前连接。
- `client` 将应用通知交给该用户已使用来源服务的连接。定向通知还须匹配连接 ID。
  断开连接时通知它使用过的服务，以便各应用释放订阅及连接专属资源。

## 应用 handler

- `require("app.agent")` 加载服务入口，`agent.handler` 负责协议分发。每次从稳定的 `REQUEST` 表查找与请求同名的函数，
  以该用户的 `agent.App` 上下文作为 `self` 调用，例如 `REQUEST.AgentChatReq(self, args, connection)`。
- 应用在自己的 VM 中持有连接对象；同一连接的设备注册、请求和断线操作共享该对象。
  需要请求来源的处理函数显式接收 `connection`。
- Agent 上线接口时同步更新应用两端的协议并实现对应的 `REQUEST` 方法。
  内部方法使用 snake_case。handler 方法体支持原位热修，新协议随应用两端发布。
