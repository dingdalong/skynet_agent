# 服务端编码与协作规范

本文件补充[仓库公共编码与协作规范](../编码与协作规范.md)，服务端架构入口见 [AGENTS.md](AGENTS.md)。
除特别说明外，下列命令均在仓库根目录执行。

## Lua 配置与对象字段

- 项目自有 Lua 运行代码通过 config 获取环境配置；`os.getenv`、`skynet.getenv`
  只在配置初始化模块中读取，不在业务执行或工具运行时读取。
- 对象用到的所有实例字段都必须在 ctor 中声明；尚未初始化的字段显式写为 `self.xxx = nil`，
  同时维护 Sumneko 类型注释。

## 热更新编码规范

- 热更新只用于修复缺陷，不用于新增功能、公开接口、持久数据格式或第三方库升级。
- 长期对象必须方法、数据分离：实例只保存业务数据，方法放在由模块返回或显式登记的稳定类表中。
- 有实例的类表不得作为模块私有变量隐藏；实例的 metatable 必须指向这个稳定类表。
- 不在实例字段、模块局部变量或长期闭包中缓存方法函数。长期 callback 可以保存，但每次执行时应通过
  `self:method()` 等稳定入口重新查找方法。
- 请求内局部变量、临时闭包和辅助函数可以正常使用；持久状态不得依赖模块局部变量或长期闭包保存。
- 可热修模块必须返回 table，顶层只做定义和依赖引用，不执行文件读写、网络请求、`skynet.call`、
  `coroutine.yield` 或修改共享数据。
- 热修缺陷修复不得改变公开方法名称、方法签名、类表层级或持久数据格式；函数体和私有辅助函数可以修改。
- 热更新时保持模块 table、类 table 和已有实例的 metatable 身份不变，只原位替换方法函数。
- 不得依赖 `_G`、registry 或业务对象遍历来更新方法；不属于稳定方法表的引用必须改为动态查找、
  使用 `skynet.inject` 紧急处理或重启服务。
- `hotfix`、`preload`、`luaext/*`、Skynet、`3rd/*`、C 模块和不可兼容的数据迁移不通过热更新处理。

审查长期对象代码时，确认：实例字段是否只有数据、方法表是否可从模块定位、是否缓存了方法函数、
热修前后接口和数据格式是否兼容。

## 测试用例

仓库级回归与验收频率遵循公共规范。服务端验证入口：

| 命令 | 覆盖 |
| --- | --- |
| `make -C server check-format test` | 服务端格式与单元测试，含公共协议、固定二进制向量及原生工具核心测试。 |
| `make -C server check` | 服务端格式、单元测试及全部服务端集成。 |
| `make -C server test-live` | 服务端真实模型网关探针。 |
| `make -C server build` | 服务端构建。 |

- 优先复用现有服务端网关测试，以真实服务进程、网络与相关命令验证受影响流程。
- 仅修改服务端测试或服务端脚本时，使用上述服务端实际流程验收，不要求运行客户端 E2E；
  不因此触发 `make check-full`。
- 真实模型验收遵循公共规范；涉及业务客户端交互或跨子系统变更时，同时遵循对应客户端与跨端验收要求。
- 启动、控制与热修操作见[开发指南](../docs/DEVELOPMENT.md)。
